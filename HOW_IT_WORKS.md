## 1. Session Lifecycle

Every mediation session goes through the following stages:

```
Room Created
     ↓
Pending Payment
     ↓
Active (Session Running)
     ↓
Timer Expired (24-hour extension window opens)
     ↓
Completed (Report generated, room locked)
```

### Status Definitions

| Status | Meaning |
|--------|---------|
| `pending` | Room created, Party A has not paid yet |
| `awaiting_party_b_payment` | Party A paid (split), waiting for Party B to pay |
| `active` | Both parties paid, session is live and timer is running |
| `timer_expired` | Timer hit 0:00 — 24-hour extension window is open |
| `completed` | Session ended, report generated, room locked forever |
| `expired` | Split payment — Party B never paid within 7 days |

## 2. Payment System

### Session Pricing

| Plan | Duration | Full Price | Split (each party) |
|------|----------|------------|--------------------|
| Starter | 30 min | $4.50 | $2.25 |
| Standard | 60 min | $7.50 | $3.75 |
| Extended | 90 min | $10.00 | $5.00 |

### Full Payment Flow
1. Party A creates room and selects "Full Payment"
2. Party A pays the full amount via Stripe
3. System sends Party B an invitation email with a join link
4. Party B joins the room (no payment required)
5. Session activates

### Split Payment Flow
1. Party A creates room and selects "Split Payment"
2. Party A pays their half via Stripe
3. System automatically emails Party B a **payment link**
4. Party B has **7 days** to pay their half
5. Once both have paid → session activates
6. If Party B does not pay within 7 days:
   - Room status → `expired`
   - Party A's money moves to their **Escrow Balance**
   - Party A receives an email notification
   - Party A can request a bank refund from admin, or use the escrow balance for a future session

## 3. Session Extension

### When Can a Session Be Extended?
- Only when the timer hits **0:00** (status: `timer_expired`)
- The extension window is open for **24 hours** after the timer expires
- After 24 hours with no extension payment → session auto-completes

### Who Can Pay for an Extension?
- **Either Party A or Party B** can pay for the extension
- There is **no split** for extensions — whoever wants to continue pays the full amount
- This avoids deadlocks where one party wants to extend but the other doesn't

### Extension Pricing

| Extension | Price |
|-----------|-------|
| +30 minutes | $2.50 |
| +60 minutes | $4.50 |

### Race Condition Prevention
To prevent both parties from paying for an extension at the same time:
- When a party clicks "Extend Session" and proceeds to Stripe, the system places a **10-minute lock** on the room
- If the other party tries to extend during this lock, they see: *"The other party is currently processing an extension. Please wait a few minutes."*
- If the payment is abandoned (Stripe checkout closed without paying), the lock automatically releases after 10 minutes
- Once payment is confirmed via Stripe webhook → lock is cleared, timer is extended, session resumes

### Extension Flow
```
Timer hits 0:00
     ↓
Status → timer_expired
Extension window opens (24 hours)
     ↓
Either party clicks "Extend Session"
     ↓
System places 10-minute lock on room
     ↓
Party redirected to Stripe checkout
     ↓
Payment confirmed via webhook
     ↓
Lock cleared, timer extended, status → active
Session resumes
```

## 4. Session Completion

A session is marked **completed** when:
- The timer expires AND no extension is paid within 24 hours, OR
- The session is manually ended (future feature)

### What Happens on Completion
1. Room status → `completed`
2. Room is **permanently locked** — no more messages, no more extensions
3. **Mediation Report** is automatically generated by Lex AI
4. Report PDF is emailed to both Party A and Party B
5. Report is available for download from the dashboard

### After Completion
- Both parties can download the report from their dashboard
- The room page shows "Download Report" button only
- No other actions are available

## 5. Mediation Report

Every completed session generates a formal PDF report containing:

1. **Case Summary** — Overview of the dispute
2. **Party A's Position** — Arguments and evidence presented
3. **Party B's Position** — Arguments and evidence presented
4. **Evidence Reviewed** — List of all uploaded documents
5. **Factual Findings** — Objective facts established during the session
6. **Contradictions Identified** — Inconsistencies between statements and evidence
7. **Legal Framework** — Relevant laws and principles for the jurisdiction
8. **Resolution Recommendation** — Lex AI's suggested fair resolution
9. **Confidence Score** — AI confidence in the recommendation (0–100%)
10. **Next Steps** — Recommended actions for both parties

**Disclaimer on every report:**
> *"This report has been generated by Lex, an AI-powered mediation assistant. This is not legal advice. Consult qualified legal professionals before making decisions based on this report."*

## 6. Referral System

### How It Works
- Every user has a unique referral code (format: `FM-XXXXXX`)
- Users share their referral link: `https://firstmediator.com/register?ref=FM-XXXXXX`
- When a referred user **completes their first paid session**, the referrer earns **10 free minutes**

### Free Minutes
- Earned minutes are stored in the user's wallet as "Free Minutes"
- Free minutes can be used to:
  - Reduce the cost of a new session
  - Extend an active session
- Free minutes expire **12 months** after being earned
- Users receive an email 30 days before expiry

### Referral Rules
- Self-referrals are blocked
- Pending referrals expire after **90 days** if the referred user hasn't completed a session
- Maximum 50 successful referrals per user per month

### Admin Control
The following referral settings are configurable from the admin dashboard:
- Minutes awarded per referral (default: 10)
- Pending referral expiry (default: 90 days)
- Free minutes expiry (default: 12 months)
- Max referrals per month (default: 50)

## 7. Wallet System

Every user has a wallet with three balances:

| Balance | Description |
|---------|-------------|
| **Credits Balance** | Spendable credits (future: top-up feature) |
| **Escrow Balance** | Held funds from expired split payments — refundable by admin or usable for future sessions |
| **Free Minutes** | Earned from referrals — used to reduce session costs |

### Escrow Balance
- Money moves to Escrow when a split payment expires (Party B didn't pay)
- Admin can release escrow as a bank refund
- User can also apply escrow balance to a future session

## 8. FM Refer (Lawyer Directory)

When a mediation session cannot be resolved by Lex AI, users can escalate to a real lawyer through **FM Refer**:

1. User browses the lawyer directory (filtered by jurisdiction and speciality)
2. User selects a lawyer and submits their case
3. Lawyer receives the full transcript, evidence, and Lex report
4. Lawyer provides a **Legal Opinion Report** within 48–72 hours
5. FirstMediator earns a **commission** (15–25%) on the referral fee

## 9. Technical Architecture

### Stack
- **Backend:** Laravel 12 (PHP)
- **Frontend:** Blade Templates + Alpine.js
- **Styling:** Tailwind CSS
- **Database:** MySQL
- **Cache/Timer:** Redis
- **Payments:** Stripe (Checkout + Webhooks)
- **AI Mediator:** Claude API (claude-sonnet-4-20250514)
- **Email:** SMTP (firstmediator.com)
- **PDF Generation:** DomPDF

### Real-time Updates (Polling)
Since the platform is hosted on cPanel (shared hosting), real-time updates use **efficient polling** instead of WebSockets:
- Frontend polls the server every **2 seconds** for new messages and timer state
- This gives a near-real-time experience without requiring WebSocket infrastructure
- Timer is stored in Redis and decremented server-side every second via a scheduled command

### Background Jobs (Cron)
Two cron jobs run every minute on the server:

```bash
# Process queued jobs (report generation, Lex AI responses, emails)
* * * * * php artisan queue:work --stop-when-empty

# Run scheduled tasks (timer decrement, extension window checks, split payment expiry)
* * * * * php artisan schedule:run
```

## 10. Security

- All payments processed by **Stripe** — no card data touches our servers
- Stripe webhook signature verified on every webhook call
- CSRF protection on all forms
- Session authentication via Laravel Sanctum
- Rate limiting on login attempts
- All evidence files stored securely (local storage, moving to Cloudflare R2)
- Passwords hashed with bcrypt (12 rounds)
